## C. 🔴 The launch blocker, found and fixed

CI failed on `dcba429a7` with *"the page states 137 legs; the explorer file carries 177"*. Investigating found **two**
defects, and the red test was the lesser one.

1. **A static artifact's eligibility claim ages into a lie (user-facing, release-blocking).** `/build/custom` resolves
   its eligible-leg pool when the page is BUILT, and nothing re-checked it afterwards: `parlays-explorer.tsx` filtered
   only on `isDetailOmitted`/sport and never compared a leg's kickoff to the reader's clock, and `build-experience.tsx`
   — the more actionable surface, where legs go onto a card — had no start filter at all. Measured on production: the
   artifact generated **00:06:36Z carried 40 legs whose games began 00:10:00Z**, still rendered as actionable at 00:23Z.
2. **Two clocks, one number (the CI failure).** The page and `data/build/explorer-slate.json/route.ts` each called
   `new Date()`, and `next build` renders a page and a route handler in **separate worker processes**, so the
   module-level slate cache is not shared. A first pitch between the two renders left two evaluations of one question
   presented as one number.

**Fix — one rule, one `asOf`.** `eventStarted` was private to `eligible-leg.ts`, which is precisely why no client
surface could share it. It now lives in the node-free contract as `legHasStarted` (**fail closed**: an unknown or
unparseable start counts as STARTED) and is re-applied against the READER's clock, re-ticked each minute, by the
explorer, the lazy wrapper's stated count and the builder pool. Both renders resolve the pool at `buildAsOfIso()` — the
instant `scripts/build-info.mjs --emit` stamps before `next build` — so the page's count and the artifact's pool are the
same evaluation by construction. `startTime` now travels on identity-only rows, on builder atoms and through
`hydrateBuildLeg`.

⚠ **Hydration is field-by-field.** Omitting `startTime` there would not have shown stale legs — the fail-closed gate
would have silently emptied the entire pool. Only the type error revealed the gap.

**Guards strengthened, never weakened.** The LIVE assertion additionally proves the artifact publishes `asOf`, that every
row carries `startTime`, and that no leg had already started at its own `asOf`. `explorer-start-gate.test.mjs` proves
the contract against **injected instants**: the fail-closed rule, a partially-started slate, an entirely-upcoming slate,
the overnight/empty state, omitted rows that cannot pad a count, the one-home wiring, and that `saveEligibility` still
refuses a started event. The `world-cup-closeout` pin moved to the new gate because the live set is a strict **subset**
of `eligibleCount` — the chip can appear in strictly fewer cases, never more — with the reasoning recorded in the test.

**Verified after the fix:** post-build artifact page **84** == artifact **84**, every row carrying `startTime`, **0**
legs started at `asOf`; live production recheck at 01:12Z identical. Note the live sample had no started legs because
the artifact was 15 minutes old — the client filter under a partially-started slate is proven by the injected-time
suite, not by that sample.
