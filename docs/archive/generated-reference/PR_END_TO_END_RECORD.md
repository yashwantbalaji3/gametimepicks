## 3. Business-positioning summary

GameTimePicks has evolved from an NBA-oriented projections board into a broader sports analytics web property with a polished consumer UI, daily projection and settlement workflows, public results tracking, suggested parlays, a paper-only Bank Builder, and an Events/Sports hub for non-modeled sports. The central product promise should remain disciplined and transparent analytics, not guaranteed outcomes. The acquisition-grade value lies in the codebase, data/automation pipeline, UX iterations, operational history, and the transparent learning loop around model performance.

The project has several important trust guardrails: no fabricated odds, no fabricated schedules, no unsupported-sport picks, no same-slate contamination, no public leakage of May 25/26 into post-May-27 public hit rates, and no user-facing betting language such as “lock,” “guaranteed,” “risk-free,” or similar hard-banned claims.

## 4. System architecture overview

### 4.1 Frontend

- Framework: Next.js 14 with React 18 and TypeScript.
- Styling: Tailwind CSS with a premium gold/vault visual language after the late-May rebuilds.
- Static output/start script: `next build` plus `serve out`.
- Core pages include Home, Projections, Parlay Lab, Bank Builder, Results, Events/Sports, methodology/audit pages, and sport-specific views.

### 4.2 Backend/data pipeline

The pipeline is Python-based and lives primarily under `pipeline/`. Major responsibilities include schedule ingestion, odds/projection board generation, recent-form enrichment, confidence guardrails, parlay optimization, curated snapshots, Monte Carlo shadow modeling, grading/settlement, audit generation, and workflow support.

Representative files include `generate_daily_board.py`, `fetch_odds_data.py`, `fetch_nba_data.py`, `attach_recent10.py`, `confidence_guardrails.py`, `parlay_optimizer.py`, `snapshot_optimizer.py`, `snapshot_parlays.py`, `grade_optimizer.py`, `grade_parlays.py`, `settle_results.py`, `audit_daily.py`, `audit_signal_policy.py`, and `model_audit.py`.

### 4.3 Automation

GitHub Actions are used for daily/triggered projection refresh, settlement, and auto-refresh operations. A major theme across the PR history is making automation safer: avoiding dry-run overwrites, avoiding provider timeouts, capping enrichment runtime, adding skip inputs, and separating active-slate/projection state from settled-results state.

### 4.4 Data/product boundaries

- MLB and NBA are the only projection/parlay sports in the latest documented product state.
- NHL, WNBA, UFC, FIFA/World Cup, IPL, and MLS are schedule-only or event-hub surfaces unless/until a full model and grading path exists.
- EPL remained “coming soon” in the latest handoff because a reliable published fixture set was not available at that time.
- Bank Builder is explicitly paper-only/educational.
