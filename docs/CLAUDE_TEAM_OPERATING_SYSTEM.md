# The Claude Operating System for GameTime Picks

*How to run GameTime Picks as a one-person company with Claude (Chat, Code, and Cowork agents) as the
team. This is the index — each role links to the runbook, prompt library, and workflow docs that make it
executable today. Everything here is grounded in scripts and gates that ALREADY exist in this repo.*

## The prime directives (every role obeys these)
1. **Canonical money changes ONLY through official settlement.** `portfolio.json` / `banked-ladders.json`
   are sacred. Every non-settlement script is md5-guarded against moving them.
2. **No fabrication.** Odds, scores, props, portraits, logos, hit-rates, EV — real source or a clean
   deterministic fallback, never invented.
3. **Fail closed.** Missing data → say so; never publish a guess. A red gate blocks the deploy.
4. **Pending is not a loss.** Official-final only; a game in progress stays honestly pending.
5. **No forced cards.** When the slate can't field a strong pick, the product shows a no-play with a reason.

## The single source of machine state
`app/public/data/admin/status.json` (generated by `build-admin-status.mjs`) is the one file every role and
agent reads first to answer *"what is the state and what is the next action?"* — canonical money, the
money-gate cross-check, today's slate, the active Bank Builder / Moonshot lanes, the last settlement, and a
derived `nextAction`. It is read-only and derived; the authoritative gates below are still the truth.

## The authoritative gates (the "definition of done")
| Gate | Command (run from `app/`, `export TSX_TSCONFIG_PATH="$PWD/tsconfig.json"`) |
|---|---|
| Money integrity | `npx tsx scripts/verify-money-integrity.mjs` |
| Forensic audit | `npx tsx scripts/forensic-money-audit.mjs` |
| Health | `npx tsx scripts/health-check.mjs --today <YYYY-MM-DD>` |
| Idempotence | `npx tsx --test src/lib/mr-dub/ledger-idempotence.test.mjs` |
| Types | `npx tsc --noEmit -p tsconfig.json` |
| Tests | `npx tsx --test $(find src -name '*.test.mjs')` |
| Build | `npm run build` |
| Production smoke | `npx tsx scripts/smoke-test-production.mjs` (post-deploy) |

**Never deploy red.** If any gate fails, fix or revert before pushing.

## The team (Claude roles)
Each role is a hat you put on with a prompt from [CLAUDE_PROMPT_LIBRARY.md](CLAUDE_PROMPT_LIBRARY.md). One
Claude session can wear several hats in a day; the point is the *ownership + expected output + gate*.

| # | Role | Owns | Expected output | Must pass |
|---|---|---|---|---|
| 1 | **Ops Manager** | The daily loop end-to-end | A completed [DAILY_CLAUDE_RUNBOOK](DAILY_CLAUDE_RUNBOOK.md) run + a one-paragraph status | All gates green; production smoke 9/9 |
| 2 | **Quant / Model Analyst** | Win/loss review, reliability weights | `docs/MODEL_REVIEW_<date>.md`; weight change ONLY if justified | [MODEL_LEARNING_LOOP.md](MODEL_LEARNING_LOOP.md); label proven/directional/insufficient |
| 3 | **Product Manager** | Product status + daily card decisions | The approved Bank Builder / Moonshot card (or a documented no-play) | Approved-card lock; team/game markets only; ≤3 legs |
| 4 | **QA Engineer** | Every page is clean | A page-by-page pass table (undefined/NaN/broken-img/stale/Pass-lean = 0) | Build render-check; 3-click nav intact |
| 5 | **UI/UX Designer** | Nav, cards, visuals, mobile | A prioritized fix list + safe implementations | Reduced-motion safe; deterministic asset fallbacks |
| 6 | **Data Engineer** | Odds, props, schedules, portfolios | A fresh, consistent slate (`refresh_daily_products.sh`) | Money md5 unchanged; health gate |
| 7 | **Launch Manager** | Deploy, verify, release notes | Logical commits, a live deploy, smoke proof, a changelog line | Rebase-safe push; smoke 9/9; production spot-checks |

### Role → prime script
- **Ops Manager / Launch Manager** → `roll_to_next_day.sh` (the one-command daily cycle), or the manual
  chain in the runbook. `smoke-test-production.mjs` for verification.
- **Data Engineer** → `refresh_daily_products.sh --date <D>` (display-only, md5-guarded).
- **Product Manager** → author `bank-builder-approved.json` → `promote-bank-builder-proposal.mjs --apply`
  (md5-guarded; restart the lane first if stopped).
- **Quant** → `settle_soccer_day.sh` output + settled ledger → `MODEL_REVIEW_<date>.md`.
- **QA** → `npm run build` then the render-audit grep in the runbook.

## How the pieces fit
```
                       admin/status.json  ◄── build-admin-status.mjs (read-only, derived)
                              ▲
  Data Engineer ─ refresh_daily_products.sh ─┐
  Product Manager ─ approve + promote ───────┤
  Ops Manager ─ roll_to_next_day.sh ─────────┼─► canonical (portfolio.json) ── official settlement ONLY
  Quant ─ settle + MODEL_REVIEW ─────────────┤
  QA ─ build render-audit ───────────────────┤
  Launch ─ push + smoke ─────────────────────┘
```
