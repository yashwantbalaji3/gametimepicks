## C. The three-owner contract (the Phase 6 lesson, made structural)

```
PRE-GAME FORECAST      LIVE EVENT STATE      FINAL RESULT
immutable              ephemeral             canonical
model-owned            provider-owned        settlement-owned
```

- **Rule A** is enforced by absence: `forecast-join.mjs` exports six read-only functions and nothing
  that writes, so there is no call a future author could make. A test enumerates that surface.
- **Rule B**: freshness is derived on the READER's clock. One envelope is FRESH at +10 s, DELAYED at
  +60 s, STALE at +300 s — pinned with injected clocks, never `Date.now()` in a test.
- A live FINAL **does not settle anything**. No file write and no settlement call on the live path.

beside a market price dressed as a GameTime projection. Pinned by a test that fails if per-player
simulation output ever appears.

stated from fetch age — the weaker claim, made as the weaker claim.

## E. Found while verifying — each is now pinned by a test

1. ⚠ **ESPN's scoreboard defaults to the CURRENT week, and `dates=` is the event's ET date, not its
   UTC date.** DET @ BUF kicks off `2026-09-18T00:15Z` and is returned by `dates=20260917`; `20260918`
   returns **zero** events. Three Week 3 games rendered "no live data source covers this game" with
   their data one parameter away. The ET date is derived with `en-CA` in `America/New_York` so no
   manual part assembly can transpose month and day.
2. ⚠ **A browser can serve a stale refusal from its PRIVATE cache**, and a stale refusal is
   indistinguishable from a real one. `Cache-Control` now carries `max-age=0` alongside `s-maxage`, so
   only the shared edge may serve from cache. `max-age=0` is asserted explicitly, not assumed.
3. ⚠ **A family's model state varies per board** — `player_rush_yds` is PUBLISHED on the week-3 board
   and ESTIMATE on the week-2 one. The gate reads the state from the board in hand; hard-coding either
   answer would let a demoted family render on the week it was demoted.
4. ⚠ **My own banned-phrase guard fired on the comments documenting the ban.** The scanner now
   partitions code from string literals (a regex over raw text finds the words inside the very
   comments that forbid them; naive comment-stripping eats the `//` in a URL), and a mutation probe
   proves it still catches a real violation — including the inverse probe, that a comment about the
   ban is not itself a finding.
