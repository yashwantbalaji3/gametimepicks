## 1. What shipped

`/ask/` — a static chat shell over a new serverless function at `/api/ask/`. Fourteen bounded tools
wrap existing owners. The model plans and writes; it never sources a sports fact.

Full design: **`docs/ASK_GAMETIME.md`**.

```
/ask/  (static)  →  POST /api/ask/  →  _ask-core (pure decisions)
                                     →  reducer → planner → executor → evidence
                                     →  verifier → writer → claim/link validator → stream
```

## 4. ⚠ The NBA dormant-key rule

`publicRiskSections.<profile>.nba` exists in **every** optimizer snapshot and is **always empty**
(`sourcePools.nbaCount: 0`, verified 09-10 → 09-17). The capability registry says NBA is
`HISTORICAL_ONLY`, `canEnterPredictionProducts` false.

Eligibility is **derived from the registry at two independent boundaries** — the builder drops
ineligible cuts (recording each in the manifest) and the adapter refuses them again at read time,
*even when non-empty*. A test populates an NBA cut deliberately, because a check that only ever sees
an empty array cannot tell "we filter it" from "it happens to be empty".

**Never infer sport support from a JSON key.**

## 5. ⚠ Verifier false-positive classes (all found by the eval, all fixed)

A guard that fires on correct content gets switched off. Six were found in my own verifier:

1. **Pattern order** — the year regex stripped `2026` from `2026-09-17`, leaving `-17`. *Every* dated
   answer was rejected. The most specific pattern must run first.
2. **Own-sentence numbers unregistered** — "per 100 staked" is text the evidence writes, then the
   verifier demanded a source for `100`. A fact's own words cannot be an unsupported claim.
3. **Identifiers read as numbers** — `opt_2026-09-17_..._513c61734f51` produced four phantom claims.
4. **Negation blindness** — "GameTime does **not** publish a price-aware expected value" was rejected
   as an EV claim. The scope must be the **sentence**; a 40-character window still failed on a
   50-character clause.
5. **One-directional pause check** — "picks the Over/Under" slipped through while "publishes no pick"
   (the correct explanation) was flagged. English puts the verb either side.
6. **Small-integer exemption** — any integer 0–10 was exempt as a "counting number". In a baseball
   product that exempts runs, innings, hits and leg counts: "the Mets scored 8" passed against
   evidence saying 5. **Removed**; the golden set still scores 91/91 without it.

Also: two **hard gates measured the wrong property** — "numeric faithfulness" failed whenever the
verifier *caught* something, scoring the safety mechanism working as a failure.

## 6. ⚠ Infrastructure defect found and fixed

`quality-gate.yml`'s **push** filter did not include `app/api/**` or `app/vercel.json`. The Live
gateway, the analytics collector and the slip reader are all production runtime code that had been
landing on `main` with **no gate run** since they shipped. The `pull_request` trigger used `app/**`
and did cover them — which is exactly why it was invisible: PRs were green and pushes ran nothing.

Fixed, with a contract test asserting **both** directions: `app/api/**` triggers the gate, and the
filter is **not** widened to `app/**` (which would make every nightly data commit rebuild the site).

## 7. Operational notes

### Daily vs committed artifacts

| Artifact | Committed? | Why |
|---|---|---|
| `entities`, `matchups`, `help`, `recent/*` | ✅ committed, `ask:check` guards | slow-moving |
| `forecasts.json`, `parlays.json` | ❌ built by `npm run build`, gitignored | change several times a day |

`scripts/vercel-ignore-build.sh` builds on any `app/` diff, and bot data commits touch
`app/public/data/**` — so the deploy's forecasts are always the deploy's forecasts.

### ⚠ Traps for the next session

- **`prune-internal-routes.mjs` keeps only NAMED `/data` prefixes.** `ask/v1/` is now listed. Omit a
  prefix and the page renders perfectly while every tool returns `ASSET_UNAVAILABLE` in production only.
- **`ask:eval` must run AFTER the build.** It drives the real tool layer against the *published*
  assets. Run before, and it measures its own plumbing.
- **`npx tsx`, not a pinned `tsx`.** Pinning was tried and reverted: the locally-installed build
  resolves `.ts` named exports differently and the whole suite went red. Pinning it properly is a
  toolchain change with its own review.
- **Lab season ids are sport-prefixed** (`NFL-2025`, `EPL-2025-26`). A bare "2025" must be resolved.
- **Last-N is sharded** by `recentShardOf(playerId) % 8`. Unsharded NFL was 2,759 KB against a 3 MB
  loader ceiling — 8% headroom is a countdown, not headroom.
